# Contributing

Gracias por contribuir. Siga estas reglas básicas:

1. Abra un issue describiendo el cambio antes de un PR grande.
2. Escriba tests para cambios en lógica (limits, idb, backup).
3. Use `npm test` y verifique que todo pase antes de enviar PR.
4. Mantener PRs pequeños y enfocados.

Estructura de ramas: main = estable; feature/* para trabajo en curso.
